# 网站双语维护

[English](i18n.md)

网站提供完整的中英文页面，包括现有十五篇文章。默认使用英文。语言选择与主题分开，不改变项目标识、文章日期、来源链接或数据格式。

## 路由与语言选择

- `/en/` 和 `/zh/` 是明确的语言根路径，同一路径后缀表示同一页面或文章。
- `/` 默认打开英文首页。访客此前通过切换按钮选择过中文时，会打开中文首页。存储无效或不可用时回退到英文。
- 明确的语言 URL 优先于已保存的偏好。页首切换按钮保留路径、查询参数和片段，尽可能保存选择。
- 链接在禁用 JavaScript 时仍可用，根路径提供英文跳转。旧的不带语言前缀页面与 Jekyll 文章地址跳转到中文版本。
- `/en/rss.xml` 和 `/zh/rss.xml` 分别发布对应语言的标题、摘要、分类和链接，`/en/feed.xml` 和 `/zh/feed.xml` 是对应别名。原 `/rss.xml` 与 `/feed.xml` 继续提供中文。
- 语言页面包含语言标签、canonical URL、`hreflang` 和英文 `x-default`。sitemap 列出正式语言页面，不包含兼容跳转或错误页面。

## 内容维护

介绍工作时直接说明数据校验与清洗、研究方法、结果记录和投资判断的证据，避免缺少依据的评价。

界面、项目介绍和个人页面文案位于 `src/i18n/en.ts` 与 `src/i18n/zh.ts`，使用语义键与命名插值。`src/i18n/index.ts` 解析词条，缺少译文时回退到英文，并按语言处理复数。日期使用 `Intl.DateTimeFormat`，时区明确为 `Asia/Shanghai`。

`src/data/projects.ts` 保留稳定仓库名、分组标识和 URL，通过词条键引用本地化文案。`src/views/` 共用布局和业务逻辑。

中文文章位于 `src/content/blog/`，完整英文译文位于 `src/content/blog-en/`。每对文章保留相同文件名、日期和稳定 slug，翻译标题、分类和完整正文，保留数值含义、限定条件、引用和结构。文章末尾的参考列表应链接到相同来源，详见[引用规范](article-references.md)（英文）。英文摘要按单词边界截断，英文阅读时长按词数估算，中文按字符数估算。

译文缺失时，渲染器保留中文原文，显示英文提示，并为正文标记 `lang="zh-CN"`。当前发布检查要求每篇文章都有英文对应文件，因此新文章应同时提供两种语言。文章回退和界面词条回退是不同机制。

## 验证

需要 Node.js 22.18 或更新版本，目录测试使用其原生 TypeScript 支持。

运行 `script/check`，检查 Astro/TypeScript、生产构建、旧地址跳转、站内链接、词条覆盖、插值、复数、回退、文章配对和引用链接。

浏览器回归：

```sh
pnpm exec playwright install chromium
pnpm run test:browser
```

脚本在空闲回环端口启动临时服务器，检查四种视口、两种语言和主题、三十个文章页面、研究来源展示、语言偏好、路径和查询参数及片段保留、旧链接、存储不可用和禁用脚本的导航。研究图表也检查加载、schema 不匹配和重试，不使用虚构结果回退。可选 `SCREENSHOT_DIR` 将临时截图保存在仓库外。CI 在静态构建之后、部署之前运行这些检查。
